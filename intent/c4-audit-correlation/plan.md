# C4 implementation plan

The owner authorized implementation of the [November 23 spec](spec.md), including R2 and R5. The candidate builds on C3. Cloud access, invitations and independent grading are outside this change.

1. Commit failing regression cases for linked preference records and required recovery telemetry. Exercise the existing SQLite-backed GCS contract service and the signed local Gradio mount.
2. Bind each submission to an opaque server-side review ID. Carry it through chat, preference writes and compact telemetry. For retries with a delivery key, bind the ID to the authenticated browser scope. An independent edit gets a new ID.
3. In the preference prefix, keep a private, conditional journal per review. Bind its service, scope and payload fingerprint on first use. Use a single generation precondition per state-write attempt. The value and its write receipt are atomic. Before replacing the receipt, checkpoint its exact generation in the earlier journal. Existing v1 values without receipts remain readable. Return only public preference fields to callers.
4. Write requested and terminal events at stable, create-only audit keys. The runtime cannot read audit or telemetry. A lost acknowledgement or a key conflict leaves the receipt unconfirmed. Let a separately authorized operator compare the complete expected object and finish its journal entry. Do not repeat an acknowledged preference change. Allow four distinct generation attempts and bound each invocation; resume a pending operation within 30 days, and only repair telemetry within its seven-day window. Private idempotency journals stay in the existing preference prefix; retaining a tombstone prevents an expired request becoming a fresh write.
5. Use the actual admission and NeMo receipts to generate a closed, four-stage recovery record in the existing cloud or local telemetry store. Give the current session the same coverage and a confirmation-gap indicator. Withhold a successful report if required receipt evidence or telemetry is unavailable. Preserve a prior block.
6. Run signed local callback tests, lost acknowledgements, concurrent/repeated deliveries, a later edit, operator reconciliation, privacy canaries, legacy reads and fixture lifecycle boundaries. Run the Python 3.13 Week 2–4 suites and offline evaluation controls. Record the observed results. Hosted CI, deployment and independent grading are separate actions.

The highest-risk boundary is a crash between a state write and its confirmation. Test storage generations and the recorded operation identity directly, including equal successive values. Counters and matching preference values alone cannot establish success. The local SQLite preference store retains its existing non-cloud contract.
